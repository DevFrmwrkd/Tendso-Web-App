# Tendso mobile app - feature inventory (read-only)

Source: `/Volumes/SSD/New Coding Projects/Tendso-App/apps/mobile` (Expo 54 / RN 0.81, expo-router 6, NativeWind + custom "editorial" primitives, Clerk, Convex via `@tendso/convex-client`). Paths below are relative to `apps/mobile/` unless noted. `._*` AppleDouble files inside `app/` are macOS junk, not routes, and were ignored.

Account roles the app knows (`services/accountAccess.ts`): `creator` (default, also what "field agent" means), `affiliate`, `admin`. There is NO shop-owner role in the app (see "Owner path" at the bottom).

Legend for "Who": agent = field agent = creator (the same role in code). "owner" = shop/business owner.

## Notes

### Owner path - is there ANY shop-owner (non-agent) path today?

**No functional one.** The app has exactly three roles: creator (the field agent), affiliate, admin. Every owner-facing capability is on the web.

- There is a platform `businessOwners` table. `convex/adminAccess.ts` `me` returns `isOwner: true` when the signed-in Clerk user has an owner row and no creator row.
- The only thing mobile does with that flag is a dead end: `(app)/_layout.tsx` shows "Continue on the web - This account type uses the Tendso website" with a Sign-out button (M-013). `account-setup.tsx` has a second "Business owner account - Manage your website at tendso.com. To become a creator or affiliate, use a different email." card, but it is unreachable in practice because the layout intercepts owners first.
- Signup / account-setup only offer Creator or Affiliate. There is no "I own a shop" choice, no owner login flow, no self-capture (an owner recording their own interview/photos), no owner payment screen, no website preview, no giveaway/OTR application UI, no owner intake.
- The only other trace of owners in mobile is admin review text: `contentSource === 'owner_intake'` is labelled "Owner submitted" and giveaway applications are flagged (M-056, M-058). Those submissions are produced by the web owner-intake flow (`convex/ownerIntake.ts`, `businessOwners.ts`), not by this app.
- Everything the agent captures is *about* an owner (owner name/phone/email fields, "ask the owner" prompts), and the owner pays on the web after the site is generated.

### Dead, duplicate, stub or stale

1. `app/(app)/onboarding.tsx` (M-007): orphan, nothing links to it; duplicate of account-setup + complete-profile; old styling.
2. `app/(app)/dashboard.tsx` (M-008) and `+not-found.tsx` (M-009): redirect shims, but still the target of ~6 `router.replace('/(app)/dashboard')` calls.

4. `services/wise.ts` (M-047): a full server-side Wise client living in the mobile bundle's source tree, only referenced by its test.
5. `h3-js` in `package.json` is not imported anywhere in mobile code (unused dependency).
6. Legacy hidden `(affiliate-tabs)/page.tsx` and `sales.tsx` redirect to the pushed affiliate tools. Money and Me now use dedicated affiliate components; they no longer re-export the field-agent screens.
7. The legacy `leads/discover.tsx` still receives explicit scrape results as JSON route parameters. The new Map home reads stored CRM/prospect/reservation data directly and does not trigger paid searches automatically; legacy search remains available under Finds → More find tools → Team CRM & search.
8. Help content is duplicated: static `help-faq.tsx` vs the Learn tab (Help Center / Field Wiki / Ask AI), which is the live, server-driven version.
9. Certificate capture/share code appears in three places (quiz, profile, notifications) via `CertificateCard`.
10. `submissions/[id].tsx`, `onboarding.tsx`, `edit-profile.tsx`, `change-password.tsx`, `certification-quiz.tsx`, `login/signup` still use legacy NativeWind (zinc/emerald) styling; most other screens use the editorial `primitives`/`tokens` design system. Visual inconsistency, not a functional bug.
11. Profile "Notifications - Manage your notification settings" opens the inbox; there are no notification settings screen or per-type toggles.

### Other things worth knowing

- Field-agent capture now has an in-app guided photo camera, optional task tiles, owner/library extras and bilingual English/Tagalog interview prompts. Physical-device camera, microphone, pause and app-background behavior still require device testing when these components change.
- Uploads: files go through `api.r2.generateUploadUrl` presigned PUT to Cloudflare R2, not Convex storage.
- Shared media limitation: removing raw capture-photo feed fallbacks and restricting the detail gallery does not fully secure media privacy. Legacy original media URLs and generic file resolvers are not fully privacy secured; these changes do not revoke existing URLs or establish private storage access end to end.
- Push token registration happens from creator Home and the authenticated online affiliate tab layout; affiliate admin preview does not mount registration.
- Secrets/config in repo: Android Google Maps API key in `app.json`; Clerk test publishable key and dev Convex URL in `eas.json` preview/dev profiles; Wise referral link hard-coded in `wallet.tsx`.
- Builds: Android APK output for preview and production; iOS bundle id `com.negosyodigital.app` (legacy brand name still used for the scheme/bundle/package; user-facing name is Tendso).
- Tendso web (`/Volumes/SSD/New Coding Projects/Tendso-App/convex/*` and Next app) owns: owner intake, giveaway, bookings, payments, website generation, domains; none of it is surfaced to owners in mobile.
